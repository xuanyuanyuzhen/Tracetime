# 时间模型 ADR 001

日期：2026-11-25。状态：记录并保留当前模型；历史归属和回拨重叠处理仍待产品决策。

## 当前决定

1. Windows适配器注入`TrackingSample`的UTC、单调毫秒和距最后输入的毫秒。核心不读取系统时钟，不依赖WPF；无须为接口名称而重写已有抽象。
2. 同一Scope的区间端点由UTC锚点加单调差值生成。单调差值为负、两次观测间隔超过15秒，或UTC偏离预期超过2秒时，结束旧Scope并以新样本重建锚点。不补记最后观测至新锚点之间的空档；恰好2秒偏差仍保留旧锚点。
3. 前台停留包含空闲；扣除空闲时先在同Scope合并空闲区间，再裁切交集。达到阈值后允许回扣此前已存区间，只改扣除空闲后的口径。不同Scope互不借用空闲证据。
4. 存储为UTC ticks；查询按调用者传入的时区划分本地日期，UI传入当前Local。日边界转换到UTC，DST日期可以是23或25小时。改变查询时区可以改变历史日期归属，不改原始UTC记录。
5. 暂停/锁屏/休眠等已知中断由适配器Stop；未知长间隔由核心自动切断。所有测试使用合成样本和固定测试时区，不更改真实时钟、时区或电源状态。

## 已证实的限制

墙钟回拨一小时后，新Scope可与旧Scope的UTC区间重叠。应用总量保留每个Scope内已观测的单调时长；`DayActivity`展示以墙钟范围规整重叠。因此这种异常情况下，排行榜总量与时间轴覆盖量可能不同。新测试刻画现状，**不表示该差异已解决**。

不能直接对所有重叠区间去重，否则会丢失回拨前后真实经历的时间；也不能简单沿用旧UTC锚点，否则历史的日期/显示时间可能持续偏离校正后的墙钟。后续需要共同决定：异常时总量与时间轴如何解释、是否保存时钟调整事件、是否持久化单调持续时间和记录时偏移。涉及schema或历史归属时另做迁移设计，本轮不迁移用户数据。
