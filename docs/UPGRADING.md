# 升级与开机启动

## 0.8.1及更早版本：换了文件夹后如何处理

开机启动保存的是程序的完整路径。解压新版到另一个目录并打开一次，不会自动修改旧版写入的启动项；0.8.1及更早版本还会把指向其他目录的TraceTime显示为未勾选。

1. 在旧版「设置与数据 → 历史备份与归档」备份历史；旧版没有该功能时，先退出，再复制整个 `%LOCALAPPDATA%\TraceTime` 目录。
2. 从托盘右键菜单选择「退出」。关闭主窗口只是收起到托盘，旧进程仍在记录；直接双击新版可能只是唤起旧进程。
3. 将新版完整解压到固定文件夹，运行其中的 `TraceTime.exe`，核对侧栏版本号。
4. 在新版「设置与数据」勾选「登录 Windows 后自动启动，收起到托盘」，点击「保存偏好」。即使原来已经开启，换了程序路径也要保存一次；必要时取消保存后再勾选保存。

同一Windows用户的历史与设置默认保存在 `%LOCALAPPDATA%\TraceTime`，独立于程序文件夹。无需将数据库复制进新版程序目录，也不要只拷贝EXE而遗漏其他程序文件。

## 0.8.2起：接续已有的开机启动选择

0.8.2当前为本地修复版，尚未发布到GitHub Release。运行完整发布包时：

- 原来未开启：保持关闭，需要用户主动勾选并保存。
- 原来已开启：退出旧实例后正常启动新版，在初始化成功后将原有启动项接续到当前EXE路径。同版本移动到新位置也适用，旧EXE已删除时也可以修复路径。
- 设置页识别旧路径上的已开启选择；勾选后保存会切换到当前程序，取消后保存会删除该启动项。
- 原启动路径仍存在且可识别为更高版本：保留该路径。若有意切回旧版本，可以在该版本显式勾选并保存。
- 若在Windows「启动应用」或任务管理器中禁用了TraceTime，程序保留该系统禁用状态，需要在Windows中自行重新启用。
- 自动接续失败会提示重新保存；没有识别把握的同名命令保持原样。演示模式、`--data-dir`独立数据运行、验证参数和开发构建均不修改自启动。

迁移只在正常启动时检查一次，不新增后台进程、联网请求或定时轮询。它仅修正启动入口；当前没有自动下载更新、安装器或跨版本进程自动接管。切换运行版本仍需先从托盘退出旧版，正常退出会保存当前记录。

## 固定目录升级

也可以将程序一直放在固定目录，例如 `D:\Apps\TraceTime`：备份历史并退出旧版后，将新包里的完整内容解压到该目录，再运行。这样EXE路径保持不变。请确认确实退出旧版后再替换文件，避免部分文件因正在使用而未更新。
